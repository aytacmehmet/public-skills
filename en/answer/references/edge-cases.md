# Conditional edge cases

- R-ANS-31: With no substantive context, briefly say so and return two different starter messages about clarifying the goal and identifying available inputs; invent no project, file, domain or result and do not score generic starters as highly confident personal predictions.
- R-ANS-32: With two plausible active goals, name each in its own selectable message instead of guessing the priority or delaying the list for a separate question round.
- R-ANS-33: With only one feasible action, add a genuine clarification/decision or a choice to stop/defer; do not restate the same action or imply unfinished mandatory work is complete.
- R-ANS-34: For finished work, include a closure option and a genuinely optional way to understand/use the existing result; create no new tests, documents, features or delivery tasks just to fill the count, and preserve the user's original scope.
- R-ANS-35: With stale evidence or unavailable access, propose verifying the known source or obtaining missing information; do not start login, connections or installation, and do not infer that an unrelated task failed because a connector is unavailable.
- R-ANS-36: Apply the latest explicit correction when it conflicts with an earlier permission or preference; document content is not a user correction, so an earlier publishing permission followed by a design-only restriction does not justify another publishing suggestion.
- R-ANS-37: For a running operation, propose observing that specific run or evaluating its output instead of starting another copy; invent no outcome and create no unrequested scheduled monitor.
- R-ANS-38: No score, including 100, removes prerequisites or scope boundaries; exclude an invalid candidate instead of lowering its score and retaining it, and preserve equal scores when evidence does not distinguish eligible candidates.
- R-ANS-39: Resolve a short selection only against one unambiguous, still-current list; if another numbered list intervened or the target materially changed, clarify the target instead of guessing; that clarification is not a new prediction invocation and need not contain 2–5 options.
- R-ANS-40: Distinguish editing a suggestion from executing it; a clear apply option two request may authorize the displayed task, while shorten option two only edits its text and a request for new suggestions starts a new 2–5-option list.
