# Five layers and independent review

- **R-BYW-EV-01** Keep all request/response/execution receipts in the private workspace, never in handoff. 1. Complete release-inspect's deterministic profile, zero-open, code and attribution checks. 2. eval-request emits three TOON packets with different context IDs and request hashes for one current spec revision/round. Each reader sees complete applicable FS-TS, project defaults and actual PNG paths/hashes; no prior answers or other-reader results. Use the host's available isolated-agent capability or independently supplied external review results. Never prescribe a provider/model/reasoning level. If independent execution is unavailable, mark NOT_RUN and stop release. Read packets progressively, but cover every requirement, collection and reference. 3. All three readers generate functional questions, each with decoded-data pointer and answer. They inspect visible draft/numbering/locking behavior. Two independently derive every acceptance scenario's outcome. A pointer existing is not semantic truth; readers and owner judge relevance. 4. At least one real visual review covers every PNG callout and UI element, matching label/layout; data-only inspection is insufficient. No vision capability means NOT_RUN, not a fabricated PASS. 5. At least one reader simulates a work plan without code and maps every decision to a pointer. Every decision missing a source is a gap. Eval finds problems; only the spec owner closes them. 6. eval-record accepts only replies bound to issued current-revision packets. Expected result agreement, coverage, pointer values and execution attestations are checked. It cannot authenticate an external model run; the owner confirms genuine isolated execution with confirm-reviews. Recorded external assertions must never be presented as fresh runs by this helper. 7. Each actual revision resets approval/rounds. Two consecutive clean rounds are mandatory; earlier findings stay in private history. Configurable round_limit defaults to 4 as a resource guard, not a quality waiver. At the limit request a decision, never silently continue or relax. 8. Never use fabricated test records in a real handoff. Regression fixtures simulate receipts to exercise mechanics; no real LLM/SAP eval was performed by their existence. Test semantic claims remain NOT_RUN until actual runs. Confirmed release serializes only anonymous counts/layer/round results into readiness-report.toon. No reader, agent, model, provider or tool names are exported. 9. Seeded errors exercise each deterministic category. Developer feedback adds a regression; track delivered-spec error count in the private ledger. No manufactured precision/quality score.
