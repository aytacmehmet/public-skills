# Scoped checks and final independent review

- **R-BYW-EV-01** Intermediate edits use check-plan with the physical assets root; hashes bind actual asset bytes, checker/schema bytes and dependency records. Reuse only actual passed unchanged checks; changed dependencies invalidate downstream units. Store results with check-record, do not infer PASS. This cache never replaces final release gates or records a provider run. Defer whole-package readers until the consultant questions and architecture/reference contract stabilize; do not run every check after every patch.
- **R-BYW-EV-02** At the final snapshot run deterministic profile/consultant closure/architecture/reference/neutrality checks, run preflight with the physical assets root, then issue three fresh isolated eval-request packets containing required local reference content and dependency contracts. All readers see applicable functional data, defaults and actual PNGs. The first two scenario readers receive test inputs without test_cases.expected; the third receives the full specification. No reader sees another reader's answers. Return a functional question for every requirement with requirement_ref, /requirements/N/statement pointer and its observed answer; provide concrete plan pointers covering objects, architecture constraints, dependencies and open delegated decisions that exist. Explicit bounded developer decisions remain delegated; their context and constraints must suffice without outside documents. Two readers independently derive every acceptance outcome; at least one inspects real PNG layout/callouts and one simulates a code-free architecture/work plan. Missing business information, references or contradictions are blocking findings.
- **R-BYW-EV-03** eval-record binds current revision, issued role/context/request, coverage, scenario results, execution receipts and parsed response hash (excluding controller-supplied response_sha256/execution_evidence). Protocol 3.3 adds role/oracle admission; legacy 3.0/3.1/3.2 packets are historical read-only and require fresh current-protocol execution/owner confirmation for credit. Compare reader-1 and reader-2 by issued identity, never array position; reader-3 sees the full specification. Require two consecutive clean final rounds and genuine confirm-reviews; helpers cannot authenticate providers. round_limit is a resource guard. Missing agents/vision is NOT_RUN; synthetic regressions are not LLM/SAP proof.
- **R-BYW-EV-04** Final batch verifies all separate ZIP inventories/hashes, role names, local document/text/ID/pointer references, source bindings, technical decision readiness, contract/version consistency and rollout order once before atomic publication. Only anonymous readiness is exported; approvals, execution receipts and cache stay private. Keep unresolved developer choices explicit, not declared coding-ready. Developer feedback is a regression and creates a new delivery version. Do not claim measured speed/token or universal semantic quality without a separate authorized experiment.

- **R-BYW-EV-05** Preserve complete sources once per file hash in source_pool and resolve source_id/path/sha256/pointer. Initialize Reader once or repeat --reference-id in one read-reference command for multiple pointers; single-ID output stays compatible. Preflight/issuance block explicit current-case oracles and peer replies in scenario-visible spec, sources, contracts and supplied text assets. Do not silently redact originals or omit required business content; resolve the source contract before dispatch. Validate canonical and actual encoded volume before writing, within 16 MiB per packet. Frozen legacy controllers/packets/hashes stay unchanged; --allow-legacy grants historical reading only.
