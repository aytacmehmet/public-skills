# Scoped checks and final independent review

- **R-BYW-EV-01** Intermediate edits use check-plan's input/dependency/checker hashes. Reuse only actual passed unchanged checks; changed dependencies invalidate downstream units. Store results with check-record, do not infer PASS. This cache never replaces final release gates or records a provider run. Defer whole-package readers until the consultant questions and architecture/reference contract stabilize; do not run every check after every patch.
- **R-BYW-EV-02** At the final snapshot run deterministic profile/consultant closure/architecture/reference/neutrality checks, then issue three fresh isolated eval-request packets. Readers see complete applicable data, defaults and actual PNGs, not other readers' answers. Ask functional questions with relevant pointers/answers. Explicit bounded developer decisions remain delegated; their context and constraints must suffice without outside documents. Two readers independently derive every acceptance outcome; at least one inspects real PNG layout/callouts and one simulates a code-free architecture/work plan. Missing business information, references or contradictions are blocking findings.
- **R-BYW-EV-03** eval-record checks issued packet, actual revision, independence, coverage, values, scenario agreement and execution attestations. Only genuine owner confirmation via confirm-reviews is accepted; helpers cannot authenticate external model runs. Two consecutive clean final rounds are required. round_limit is a resource guard, not a quality waiver. No model/provider choice, fake reviews or automatic closure. Missing agents/vision is NOT_RUN and blocks delivery. Reviewers are used only in an actual handoff flow when available/authorized; plugin code regression fixtures are synthetic and are not LLM/SAP proof.
- **R-BYW-EV-04** Final batch verifies all separate ZIP inventories/hashes, role names, local document/text/ID/pointer references, source bindings, technical decision readiness, contract/version consistency and rollout order once before atomic publication. Only anonymous readiness is exported; approvals, execution receipts and cache stay private. Keep unresolved developer choices explicit, not declared coding-ready. Developer feedback is a regression and creates a new delivery version. Do not claim measured speed/token or universal semantic quality without a separate authorized experiment.
